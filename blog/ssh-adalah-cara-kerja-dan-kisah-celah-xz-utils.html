SSH Adalah Kunci Utama Server Internet dan Kisah Nyata Saat Seluruh Dunia Hampir Diretas Tanpa Sadar

Oleh I Putu Dicky Adi Pranatha • 16 November 2026 • 13 min read • Frontend & Code
Inspirasi Video & Rujukan Dokumenter

Alur cerita dalam artikel ini terinspirasi dari dokumenter kanal YouTube Veritasium berjudul "The Internet Was Weeks Away From Disaster and No One Knew" (How Someone Almost Hacked Every Linux Server on the Planet). Kami merangkai kisah dokumenter tersebut dari awal hingga akhir dengan bahasa sesederhana mungkin, mulai dari apa itu SSH (Secure Shell), sejarah kelahirannya pada tahun 1995, cara kerja gembok Public Key dan Private Key, hingga bagaimana operasi penyusupan Jia Tan ke dalam XZ Utils nyaris memasang backdoor di pintu masuk SSH jutaan server dunia.

Tonton Dokumenter Veritasium di YouTube Kanal: Veritasium • Topik: Open Source, Enkripsi SSH, dan Operasi Backdoor XZ Utils (CVE-2024-3094)
TL;DR / Ringkasan Cepat
  • SSH (Secure Shell) adalah jalur terowongan rahasia yang terenkripsi (diacak dengan rumus matematika) agar seorang developer bisa mengendalikan komputer server dari jarak jauh lewat layar terminal tanpa takut password atau perintahnya diintip orang di tengah jalan.
  • Protokol ini diciptakan pada tahun 1995 oleh peneliti Finlandia bernama Tatu Ylönen untuk menggantikan protokol lama bernama Telnet yang mengirim ketikan secara telanjang (plaintext), dengan memanfaatkan pasangan gembok Public Key di pintu server dan anak kunci Private Key di laptop pemiliknya.
  • Sesuai alur dokumenter Veritasium, karena pintu depan OpenSSH terlalu kuat untuk dijebol langsung, sosok misterius bernama Jia Tan menghabiskan 2,5 tahun menyusup ke proyek kompresi file XZ Utils milik relawan Lasse Collin demi menyelundupkan backdoor ke dalam proses login SSH, sebelum akhirnya ketahuan oleh engineer Andres Freund gara-gara delay waktu login sebesar 500 milidetik.

Secara sederhana, SSH adalah jalur terowongan rahasia di internet (singkatan dari Secure Shell) yang dipakai oleh developer atau pengelola sistem untuk masuk dan mengendalikan komputer server dari jarak jauh secara aman. Bayangkan komputer server tempat menyimpan website, aplikasi mobile banking, atau game online itu seperti sebuah komputer besar yang dikunci di dalam gedung ber-AC di Singapura atau Amerika Serikat. Komputer server itu tidak punya layar monitor dan tidak dipasangi keyboard. Supaya developer yang sedang duduk di kamar kos di Indonesia bisa menyalakan program, memindahkan file, atau memperbaiki bug di komputer tersebut, mereka membuka layar hitam bernama terminal di laptop, lalu menyambungkannya ke server lewat terowongan SSH.

Karena SSH adalah satu-satunya pintu gerbang utama untuk mengatur isi server, keamanan pintu ini menentukan hidup dan matinya internet. Sekarang bayangkan, bagaimana jika ada seseorang yang diam-diam berhasil memasang lubang kunci rahasia (backdoor) di pintu SSH pada jutaan server di seluruh dunia? Tanpa perlu tahu password pemiliknya, orang itu bisa langsung nyelonong masuk sebagai penguasa tertinggi (root access), mematikan layanan rumah sakit, menguras data perbankan, atau meruntuhkan jaringan internet global dalam semalam.

Kisah mengerikan itu bukanlah cerita film hacker di bioskop. Seperti yang dibedah dalam video dokumenter kanal YouTube Veritasium, pada akhir Maret 2024 seluruh internet dunia benar-benar hanya berjarak beberapa minggu dari bencana tersebut, dan nyaris tidak ada yang tahu. Agar kamu benar-benar paham mengapa pintu seaman SSH bisa hampir kecolongan dari dalam, kita akan mengikuti alur cerita video tersebut langkah demi langkah dengan bahasa paling gampang: mulai dari urusan printer macet yang melahirkan gerakan open-source, cara kerja gembok Public Key dan Private Key pada SSH, akal bulus Jia Tan menyusup ke aplikasi kompresi XZ Utils, hingga bagaimana jeda setengah detik menyelamatkan internet kita.

Bagaimana Fondasi Internet Modern Berdiri di Atas Pundak Relawan Open Source yang Kelelahan

Sebelum kita membahas apa itu SSH dan bagaimana pintu keamanannya disusupi, dokumenter Veritasium mengajak kita melihat satu fakta menarik yang jarang disadari pengguna internet awam. Saat kita memakai laptop sehari-hari, kita terbiasa menggunakan sistem operasi berbayar seperti Windows buatan Microsoft atau macOS buatan Apple. Karena itu, banyak orang mengira komputer server raksasa di internet juga memakai sistem berbayar milik perusahaan triliunan dolar.

Padahal kenyataannya terbalik 180 derajat. Lebih dari 90 persen cloud server dan superkomputer yang menjalankan internet dunia saat ini hidup di atas sistem operasi gratis yang kodenya dibuka untuk umum, yaitu GNU/Linux. Uniknya, seluruh gerakan kode terbuka (open-source software) ini lahir gara-gara sebuah printer kantor yang sering macet pada tahun 1980.

Dari Printer Xerox yang Macet Tahun 1980 hingga Lahirnya Sistem Open Source GNU dan Linux

Pada tahun 1980, seorang programmer bernama Richard Stallman bekerja di laboratorium AI milik kampus MIT di Amerika Serikat. Suatu hari, kantor mereka kedatangan printer laser baru yang sangat cepat bernama Xerox 9700. Sayangnya, printer mahal ini punya satu kebiasaan buruk: kertasnya sering nyangkut (paper jam). Karena printer itu ditaruh di ruangan berbeda, orang-orang yang sedang mencetak dokumen tidak sadar kalau printer sedang macet, sehingga antrean dokumen menumpuk dan waktu kerja terbuang sia-sia.

Di printer kantor yang lama, Stallman pernah mengedit sedikit source code (resep kode program) di dalamnya. Jadi, setiap kali kertas nyangkut, printer otomatis memunculkan pesan peringatan di layar komputer orang yang sedang menunggu cetakan. Stallman pun ingin memasang fitur sederhana yang sama ke printer Xerox 9700. Namun, ketika ia meminta source code tersebut, perusahaan Xerox menolak mentah-mentah. Bagi Xerox, kode program itu adalah rahasia perusahaan yang dikunci rapat (closed-source atau proprietary software).

Agar mudah membayangkan bedanya, anggap saja software itu seperti kue bolu:

  • Closed-Source Software (Kode Tertutup): Perusahaan hanya menjual kue bolu yang sudah matang di dalam kotak tersegel (seperti Windows, macOS, atau program printer Xerox). Kalau kuenya kemanisan atau printer-nya macet, kamu dilarang melihat kertas resepnya dan tidak boleh memperbaikinya sendiri.
  • Open-Source Software (Kode Terbuka): Kertas resepnya (source code) ditempel terbuka di papan pengumuman. Siapa saja di dunia boleh membaca resepnya, memeriksa apakah ada bahan beracun di dalamnya, ikut memperbaiki rasanya, dan membagikannya secara gratis.

Karena kesal dilarang memperbaiki alat yang mereka pakai sendiri, Richard Stallman memutuskan keluar dari pekerjaannya lalu memulai Proyek GNU pada tahun 1983 serta mendirikan Free Software Foundation (FSF) pada tahun 1985 untuk membangun sistem operasi yang 100 persen terbuka. Delapan tahun kemudian, pada Agustus 1991, seorang mahasiswa berusia 21 tahun di Finlandia bernama Linus Torvalds membuat jantung utama sistem operasi (disebut kernel) yang ia namai Linux, lalu mengunggahnya gratis ke internet. Gabungan peralatan GNU buatan Stallman dan kernel Linux buatan Torvalds inilah yang hari ini menjadi pondasi bagi hampir seluruh server di bumi.

Paradoks Menara Digital Triliunan Dolar yang Bertumpu pada Satu Maintainer Tak Dibayar

Meskipun sistem open-source membuat teknologi berkembang sangat cepat, ada satu celah manusiawi yang sangat berbahaya di dalamnya. Di dunia pemrograman, fenomena ini paling pas digambarkan lewat komik terkenal XKCD nomor 2347 berjudul "Dependency" yang juga ditampilkan oleh Veritasium: seluruh bangunan internet modern digambarkan seperti menara balok raksasa yang megah, tetapi bagian paling bawahnya ditopang oleh satu balok kecil yang dirawat sendirian tanpa gaji oleh satu orang sukarelawan sejak tahun 2003.

Mengapa bisa begitu? Karena saat developer di perusahaan raksasa membangun aplikasi, mereka tidak menulis semua kode dari nol. Mereka menyusun aplikasinya seperti bermain balok Lego. Sebagaimana pernah kita bahas pada artikel bagaimana celah di library kompresi Brotli memicu krisis Node2Shell, ratusan balok Lego siap pakai itu disebut library atau dependency (komponen kode yang diandalkan oleh program lain).

Salah satu balok Lego kecil yang terpasang di hampir setiap komputer Linux di dunia bernama XZ Utils (dengan mesin utamanya yang bernama liblzma). Kalau di laptop Windows kamu kenal aplikasi WinRAR atau 7-Zip untuk mengecilkan ukuran file, maka XZ Utils adalah alat kompresi file (file compression) andalan di Linux yang memadatkan paket software menjadi file berakhiran .xz supaya ukurannya mungil dan cepat diunduh.

Masalahnya, sejak sekitar tahun 2005, proyek XZ Utils yang dipakai oleh jutaan server bank dan perusahaan raksasa ini diurus nyaris sendirian oleh satu orang programmer sukarelawan asal Finlandia bernama Lasse Collin. Dalam istilah open-source, pengurus proyek seperti Lasse disebut sebagai maintainer. Selama hampir dua puluh tahun, Lasse merawat XZ Utils di waktu luangnya tanpa bayaran tetap. Ia sama sekali tidak menduga bahwa balok Lego kecil yang ia jaga sendirian itu sedang diincar oleh komplotan peretas untuk membobol pintu gerbang paling krusial di internet: SSH.

Apa Sebenarnya SSH Itu dan Mengapa Protokol Ini Menjadi Penjaga Pintu Setiap Server

Mengapa komplotan peretas kelas kakap rela menghabiskan waktu bertahun-tahun mengincar aplikasi pemadat file seperti XZ Utils? Karena target asli mereka bukanlah file .xz, melainkan pintu masuk SSH! Bagi kamu yang sedang belajar membuat website, menyewa VPS (Virtual Private Server), atau mengunggah kodingan ke GitHub, memahami cara kerja SSH akan membuatmu mengerti bagaimana seluruh server di dunia dikendalikan.

SSH adalah protokol jaringan (aturan komunikasi komputer) yang menciptakan sambungan command line atau terminal jarak jauh yang dienkripsi penuh antara laptop pengguna (SSH Client) dan komputer server tujuan (SSH Server). Kalau diibaratkan rumah, komputer server memiliki ribuan nomor pintu komunikasi yang disebut port, dan pintu resmi tempat SSH berjaga secara bawaan adalah Port 22.

Sejarah Tahun 1995 Saat Tatu Ylönen Menciptakan SSH untuk Menggantikan Jalur Telnet yang Telanjang

Supaya langsung paham betapa pentingnya SSH, bayangkan kondisi internet sebelum tahun 1995. Waktu itu, kalau seorang teknisi ingin masuk ke komputer server dari jarak jauh, mereka memakai protokol tua buatan tahun 1969 yang bernama Telnet atau perintah rlogin.

Celakanya, jalur Telnet punya satu kelemahan yang sangat fatal: Telnet mengirim setiap huruf yang kamu ketik di keyboard dalam bentuk teks telanjang (plaintext) tanpa diacak sedikit pun! Sebagaimana pernah kita bahas pada artikel sejarah password dari tahun 1961 hingga celah keamanan akun, mengirim username dan password lewat Telnet itu persis seperti kamu menulis nomor PIN ATM di belakang selembar kartu pos tanpa amplop, lalu menitipkannya secara estafet melewati sepuluh orang asing. Siapa pun yang memasang alat penyadap jaringan (network sniffer) di kabel internet kampus atau kantor bisa langsung membaca password milikmu huruf demi huruf di layar mereka.

Kejadian persis itulah yang mengguncang kampus Helsinki University of Technology di Espoo, Finlandia, pada musim semi tahun 1995:

  1. Ribuan Password Kampus Disadap Hidup-Hidup: Seseorang diam-diam memasang alat password sniffer di jaringan utama universitas. Dalam waktu singkat, ribuan username dan password milik dosen, mahasiswa, hingga perusahaan riset milik peneliti bernama Tatu Ylönen berhasil dicuri karena semuanya lewat di jalur Telnet yang telanjang.
  2. Lahirnya SSH pada Juli 1995: Kaget melihat betapa mudahnya jalur Telnet diintip, Tatu Ylönen langsung mengurung diri mempelajari ilmu pengacakan pesan (kriptografi). Hanya dalam beberapa bulan, tepatnya pada Juli 1995, ia meluncurkan program ciptaannya yang diberi nama SSH (Secure Shell) secara gratis agar tidak ada lagi password yang lewat secara telanjang di internet.
  3. Menjadi Standar Dunia Lewat OpenSSH (1999): Karya Tatu Ylönen langsung diadopsi di seluruh dunia dan disahkan menjadi standar resmi internet oleh lembaga IETF lewat dokumen RFC 4251. Pada tahun 1999, komunitas pengembang OpenBSD merilis versi open-source gratisnya yang bernama OpenSSH (dengan program penjaga pintu di sisi server yang bernama sshd atau SSH Daemon). Hari ini, OpenSSH adalah penjaga pintu standar di hampir semua server Linux di bumi.

Cara Kerja Public Key dan Private Key yang Membuat Jalur SSH Mustahil Ditebak dari Luar

Sekarang muncul pertanyaan paling seru yang juga dijelaskan dengan sangat jenius di video Veritasium: "Bagaimana cara laptop kita dan komputer server menyepakati bahasa sandi rahasia, padahal sejak detik pertama ngobrol, kabel internet di antara mereka sudah penuh dengan penyadap?"

Kalau kita memakai pengacakan biasa yang disebut Symmetric Encryption (Enkripsi Satu Kunci), kita akan menemui jalan buntu. Bayangkan kamu mengunci surat di dalam kotak besi memakai satu kunci rumah, lalu mengirim kotak itu ke temanmu di luar negeri. Supaya temanmu bisa membuka kotaknya, kamu harus mengirim anak kuncinya juga lewat kurir. Kalau kurir di tengah jalan menduplikat anak kunci itu, tamatlah rahasiamu!

Untuk memecahkan kebuntuan itu, SSH menggunakan keajaiban matematika yang disebut Asymmetric Encryption (Enkripsi Pasangan Kunci Berbeda: Public Key & Private Key), seperti algoritma RSA atau Ed25519. Cara kerjanya bisa kamu bayangkan lewat Analogi Gembok Terbuka dan Anak Kunci Pribadi berikut ini:

  • 1. Public Key (Ibarat Gembok Besi dalam Posisi Terbuka): Ketika kamu membuat kunci SSH di laptop, komputer akan mencetak dua benda berbeda. Benda pertama namanya Public Key. Bayangkan ini sebagai sebuah gembok besi yang sedang terbuka. Kamu boleh memperbanyak gembok terbuka ini, membagikannya ke seluruh dunia, dan menempelkannya di pintu komputer server (di dalam file authorized_keys). Siapa pun di internet boleh melihat gembok ini dan menekannya sampai berbunyi "klik!" untuk mengunci kotak pesan. Namun ingat: gembok tidak bisa dipakai untuk membuka gembok itu sendiri.
  • 2. Private Key (Ibarat Satu-Satunya Anak Kunci Pembuka): Benda kedua namanya Private Key. Ini adalah satu-satunya anak kunci yang cocok untuk membuka gembok Public Key tadi. Anak kunci Private Key ini disimpan rapat-rapat di dalam laptopmu sendiri dan pantang dikirim lewat kabel internet ke mana pun.

Jadi, setiap kali seorang developer mengetik ssh user@alamat-server di layar terminal untuk masuk ke server, program SSH melakukan tiga langkah jabat tangan cepat (SSH Handshake) dalam hitungan milidetik:

  1. Cek KTP Server (Host Verification): Komputer server menunjukkan identitasnya lebih dulu. Laptopmu mencocokkannya dengan daftar catatan di file known_hosts untuk memastikan kamu tidak salah masuk ke server tiruan milik penipu.
  2. Bikin Terowongan Kedap Sadapan (Session Key Exchange): Lewat rumus pertukaran kunci (Diffie-Hellman), laptop dan server meracik satu kunci pengacak khusus yang hanya berlaku untuk obrolan hari itu saja. Sejak detik ini, semua data yang lewat sudah terbungkus rapat.
  3. Ujian Kunci Pribadi Tanpa Mengirim Password (User Authentication): Bagaimana cara server tahu bahwa kamu adalah pemilik sah tanpa kamu perlu mengirim Private Key? Server akan mengunci sebuah teka-teki acak memakai gembok Public Key milikmu yang tertempel di pintu server, lalu mengirim teka-teki terkunci itu ke laptopmu. Hanya laptopmu yang memegang Private Key asli yang sanggup membukanya dan menandatanganinya! Di dalam server OpenSSH (sshd), proses pemeriksaan tanda tangan kunci ini salah satunya dikerjakan oleh fungsi kode bernama RSA_public_decrypt. Kalau cocok, pintu server langsung terbuka lebar!

Supaya kamu punya gambaran jelas mengapa para praktisi IT selalu menyarankan memakai SSH Key ketimbang mengetik password biasa, simak tabel perbandingan tiga cara masuk ke server di bawah ini:

Aspek Perbandingan Telnet (Cara Lama 1969) SSH + Password Biasa SSH + SSH Key (Public & Private Key)
Kondisi Data di Kabel Internet Teks telanjang (Plaintext); semua ketikan dan password bisa dibaca langsung oleh penyadap Wi-Fi/jaringan. Terenkripsi penuh di dalam terowongan SSH, aman dari intipan di tengah jalan. Terenkripsi penuh dan tidak pernah mengirim kata sandi apa pun lewat kabel internet.
Ketahanan dari Serangan Tebak Sandi (Brute-Force) Sangat berbahaya dan sudah dilarang untuk pengelolaan server modern. Masih rawan ditembaki ribuan program bot otomatis yang menebak password di Port 22 tiap detik. Mustahil ditebak paksa; komputer tercepat di dunia butuh waktu miliaran tahun untuk menebak pasangan kuncinya.
Kepraktisan Buat Developer (VPS & Git) Harus mengetik ulang sandi tanpa perlindungan. Capek karena harus mengetik password berulang kali setiap mau login atau push kode. Praktis dan instan; cukup sekali tempel Public Key di server atau GitHub, langsung masuk otomatis.
Rekomendasi Terbaik Saat Ini Tinggalkan sepenuhnya untuk urusan server internet. Hanya boleh dipakai di menit pertama saat baru menyewa VPS, lalu wajib dimatikan. Wajib dipakai (terutama tipe kunci Ed25519) untuk semua server dan akun Git.

Operasi Penyusupan Jia Tan Selama Dua Setengah Tahun untuk Membobol Pintu SSH dari Dalam

Setelah melihat cara kerja gembok Public Key dan Private Key di atas, kamu pasti langsung paham mengapa para hacker maupun agen intelijen negara pusing tujuh keliling menghadapi OpenSSH. Pintu depannya terlalu kuat. Kamu tidak bisa menyadap kabelnya, tidak bisa menebak kunci matematikanya, dan tidak bisa menyelundupkan kode jahat langsung ke proyek OpenSSH karena ribuan pakar keamanan memelototi source code-nya setiap hari.

Lalu bagaimana cara menembus benteng yang pintu depannya tidak mempan didobrak? Jawabannya persis seperti taktik Kuda Troya: jangan serang penjaga pintunya, tapi menyusuplah ke pabrik pembuat baut kecil yang dipakai di dalam engsel pintu tersebut! Dalam dunia cybersecurity, taktik memutar lewat komponen pendukung ini disebut Supply-Chain Attack (serangan rantai pasok).

Taktik Social Engineering Menekan Lasse Collin hingga Menyerahkan Akses Co-Maintainer XZ Utils

Kisah penyusupan paling sabar dalam sejarah internet ini dimulai pada Oktober 2021. Waktu itu, muncul sebuah akun GitHub baru bernama Jia Tan (dengan username JiaT75). Alih-alih langsung bertindak mencurigakan, Jia Tan datang bagaikan teman kerja impian. Selama berbulan-bulan, ia rajin membantu mengirimkan patch (tambalan perbaikan kode) yang rapi dan sangat membantu ke proyek XZ Utils yang diurus sendirian oleh Lasse Collin.

Namun, begitu memasuki bulan April hingga Juni 2022, komplotan ini mulai memainkan sandiwara psikologis yang kejam (disebut social engineering). Tiba-tiba muncul akun-akun misterius bernama Jigar Kumar dan Dennis Ens di forum mailing list XZ Utils. Para peneliti keamanan siber meyakini akun-akun ini hanyalah akun palsu (sockpuppet accounts) yang dikendalikan oleh komplotan Jia Tan sendiri untuk memainkan skenario "polisi jahat dan polisi baik":

  • Akun Palsu Menyerang Mental Lasse Collin: Akun Jigar Kumar mengirim email bernada marah-marah, memprotes mengapa Lasse Collin sangat lambat merilis update, dan mempermalukan Lasse di depan umum dengan berkata bahwa proyek XZ Utils akan mati kalau tetap dipegang oleh Lasse sendirian.
  • Lasse Collin Sedang Burnout Berat: Di tengah hujan kritik tersebut, Lasse Collin menjawab dengan jujur bahwa ia memang sedang berjuang melawan masalah kesehatan mental jangka panjang dan kelelahan fisik (burnout) setelah belasan tahun mengurus proyek itu sendirian tanpa gaji. Dalam email itu, Lasse bercerita bahwa untungnya sekarang ada relawan baru yang sangat baik dan rajin membantunya, yaitu Jia Tan!
  • Kunci Gudang Kode Berpindah Tangan: Sandiwara itu berhasil seratus persen. Karena terus didesak oleh akun-akun palsu tadi, pada akhir tahun 2022 hingga awal 2023, Lasse Collin yang kelelahan akhirnya mengangkat Jia Tan menjadi pengurus pendamping (co-maintainer). Sejak hari itu, Jia Tan resmi memegang kunci utama untuk mengubah dan merilis update XZ Utils ke seluruh dunia!

Cara Backdoor di File Kompresi XZ Membajak Proses Login OpenSSH Lewat Jalur Systemd

Saat membaca bagian ini, kamu mungkin langsung bertanya-tanya: "Tunggu dulu, XZ Utils kan cuma aplikasi kompresi file mirip ZIP atau WinRAR. Sedangkan pintu login server dijaga oleh OpenSSH. Memangnya apa hubungan antara aplikasi kompresi file dengan pintu login SSH?"

Pertanyaanmu sangat tepat! Aslinya, program OpenSSH (sshd) memang sama sekali tidak memakai kode XZ Utils. Kalau kamu mengunduh OpenSSH murni dari pembuat aslinya, kuda Troya Jia Tan tidak akan mempan.

Akan tetapi, di dunia nyata, sistem operasi Linux populer seperti Debian, Ubuntu, Fedora, dan Red Hat menambahkan sedikit modifikasi pada OpenSSH mereka supaya bisa mengobrol dengan program pengatur layanan latar belakang yang bernama systemd (tujuannya sederhana, supaya OpenSSH bisa melapor ke systemd: "Hei, pintu SSH sudah nyala dan siap menerima tamu!"). Nah, di sinilah letak celahnya: library libsystemd tersebut ternyata memakai liblzma (mesin milik XZ Utils) untuk mengecilkan ukuran log file (catatan riwayat sistem)!

Gara-gara sambungan berantai itulah (sshd → libsystemd → liblzma), kode XZ Utils otomatis ikut tersedot masuk ke dalam ruang memori yang sama dengan pintu login OpenSSH! Mengetahui adanya jalur tikus tersebut, pada Februari 2024 (lewat update XZ Utils versi 5.6.0 dan 5.6.1), Jia Tan melancarkan empat langkah penyusupan yang luar biasa licik:

  1. Menyembunyikan Backdoor di Dalam "Test File" yang Rusak: Jia Tan tahu kalau ia menulis kode jahat secara terang-terangan di dalam source code bahasa C di GitHub, programmer lain pasti langsung curiga. Jadi, ia menyembunyikan kode backdoor yang sudah diacak ke dalam dua file latihan (test files) bernama bad-3-corrupt_lzma2.xz dan good-large_compressed.lzma. Kenapa tidak ada yang curiga melihat file berisi kode acak di sana? Karena setiap aplikasi kompresi file memang wajib punya folder berisi contoh file yang "rusak" untuk mengetes apakah aplikasinya bakal error atau tidak saat membuka file rusak!
  2. Membongkar Isi Bom Saat Proses Build (Compile): Saat Jia Tan mengunggah paket release file resmi berformat .tar untuk diambil oleh pengelola Linux, ia menyelipkan script tersembunyi di dalam file build-to-host.m4. Ketika komputer pusat Debian atau Fedora sedang merakit (build / compile) kode XZ Utils menjadi program siap pakai, script itu diam-diam membongkar isi test file rusak tadi lalu menyuntikkan backdoor-nya langsung ke dalam library matang liblzma.so.
  3. Membelokkan Fungsi Cek Kunci di OpenSSH: Begitu komputer server dinyalakan dan OpenSSH memanggil systemd, kode backdoor di dalam liblzma langsung aktif. Ia memakai fitur bawaan Linux bernama IFUNC (GNU Indirect Function) untuk membajak fungsi pemeriksa gembok SSH yang kita bahas tadi, yaitu fungsi RSA_public_decrypt!
  4. Lubang Kunci Master Rahasia Milik Jia Tan: Setelah fungsi RSA_public_decrypt dibajak, setiap kali ada orang mengetuk pintu login SSH di Port 22, backdoor tersebut akan mengintip lebih dulu: "Apakah orang yang mengetuk pintu ini membawa tanda tangan rahasia berjenis Ed448 milik Jia Tan?" Kalau yang masuk adalah developer biasa, SSH berjalan normal seperti biasa. Tapi kalau yang mengetuk pintu membawa Private Key rahasia milik Jia Tan, backdoor itu langsung membuka pintu selebar-lebarnya dan memberikan hak kuasa penuh (root access) untuk menjalankan perintah apa saja di server tanpa perlu login sama sekali!

Keajaiban Setengah Detik yang Menyelamatkan Internet dan Cara Mengamankan Server Hari Ini

Pada pertengahan Maret 2024, bom waktu buatan Jia Tan itu sudah berhasil masuk ke versi uji coba (testing branch) berbagai sistem Linux besar, mulai dari Debian Sid, Fedora Rawhide, hingga tahap awal Ubuntu dan Red Hat. Bahkan, komplotan Jia Tan sedang gencar membujuk para pengurus Linux agar segera memasukkan update XZ Utils itu ke versi utama (stable release) yang akan terpasang otomatis di jutaan server seluruh dunia dalam hitungan minggu.

Seluruh operasi intelijen yang disiapkan dengan sabar selama dua setengah tahun itu akhirnya gagal total hanya karena satu hal sepele yang tidak pernah diduga oleh Jia Tan: rasa penasaran seorang engineer terhadap delay setengah detik.

Kecurigaan Andres Freund pada Delay 500 Milidetik dan Jawaban atas Debat Keamanan Open Source

Di San Francisco, seorang software engineer berusia 38 tahun yang bekerja di Microsoft sekaligus pengembang database PostgreSQL bernama Andres Freund sedang mengetes performa komputernya yang memakai sistem Debian Sid. Saat sedang memeriksa layar pemantau sistem, Andres melihat ada sesuatu yang agak aneh: program penjaga pintu SSH (sshd) tiba-tiba memakan tenaga prosesor (CPU) sedikit lebih tinggi dari biasanya.

Ketika Andres menghitung berapa lama waktu yang dibutuhkan saat seseorang gagal login ke pintu SSH, ia menemukan selisih angka yang sangat kecil tetapi menyelamatkan dunia:

Fakta Delay 500 Milidetik (0,5 Detik) yang Membongkar Backdoor Jia Tan: Normalnya, proses pengecekan login di pintu SSH hanya butuh waktu sekitar 300 milidetik (0,3 detik). Namun setelah update XZ Utils 5.6.1 terpasang, proses yang sama melambat menjadi 800 milidetik (0,8 detik). Kenapa ada delay tambahan 500 milidetik (setengah detik)? Karena setiap kali ada orang mengetuk pintu SSH, kode backdoor Jia Tan harus bekerja ekstra menghitung rumus kriptografi Ed448 untuk mengecek apakah tamu yang datang itu adalah Jia Tan atau bukan!

Coba jujur pada diri kita sendiri: kalau laptop atau internet kita tiba-tiba terasa lambat setengah detik saja, apa yang kita lakukan? Hampir semua orang di bumi pasti tidak akan sadar, atau paling-paling mengira sinyal Wi-Fi sedang agak turun. Namun, Andres Freund tidak membiarkannya lewat begitu saja. Ia membuka tools pelacak performa bernama perf dan pemeriksa memori Valgrind, membongkar proses di dalam sshd, lalu melacak sumber pelambatan itu sampai ke file liblzma.so.5.6.1.

Begitu melihat ada kode aneh yang sengaja disembunyikan di dalam XZ Utils untuk membajak OpenSSH, Andres langsung mengirim email peringatan darurat ke forum keamanan dunia oss-security pada 29 Maret 2024. Temuan itu langsung diberi kode bahaya CVE-2024-3094 dengan skor keparahan maksimal 10,0 dari 10,0 (Critical). Dalam hitungan jam, seluruh pengelola Linux di dunia langsung membatalkan update tersebut dan mencabut akses Jia Tan selamanya.

Lalu, siapa sebenarnya sosok di balik akun Jia Tan? Setelah kejadian itu meledak, para peneliti memeriksa jam kerja dari ratusan Git commits (riwayat pengiriman kode) milik Jia Tan selama 2,5 tahun dan menemukan petunjuk kuat:

  • Bekerja Sesuai Jam Kantor 9-to-5 di Zona Waktu Eropa Timur / Asia Barat: Walaupun Jia Tan berusaha menyamar seolah tinggal di zona waktu Asia Timur (UTC+8), grafik jam kerjanya selama bertahun-tahun selalu dimulai pukul 09.00 pagi dan berhenti pukul 17.00 sore dari Senin sampai Jumat pada zona waktu UTC+2 atau UTC+3, serta selalu libur tepat pada tanggal merah di kawasan Eropa Timur.
  • Bukan Hacker Kamar Tidur, Melainkan Operasi Negara: Melihat betapa rapinya kode kriptografi Ed448 yang dipakai, kesabaran merawat proyek selama 2,5 tahun tanpa salah langkah, serta jadwal kerja persis pegawai kantoran tersebut, para pakar sepakat bahwa Jia Tan adalah tim operasi intelijen siber yang dibiayai oleh negara (state-sponsored actor).

Di penghujung videonya, Veritasium menutup cerita ini dengan satu pertanyaan besar yang sering membuat orang salah paham: "Kalau sistem open-source seperti XZ Utils bisa disusupi orang jahat, apakah itu artinya software tertutup (closed-source) seperti Windows atau macOS jauh lebih aman?"

Jawabannya justru sebaliknya: kita semua selamat dari bencana ini murni karena Linux dan OpenSSH adalah open-source! Coba bayangkan seandainya delay setengah detik (500 milidetik) tadi terjadi setelah kamu melakukan update pada sistem operasi tertutup (closed-source) yang kodenya dirahasiakan seperti printer Xerox di zaman Richard Stallman dulu. Di sistem tertutup, insinyur luar seperti Andres Freund dilarang keras mengintip isi source code-nya. Kalau komputer melambat setengah detik sehabis update, semua orang hanya akan mengeluh sebentar lalu menerimanya sebagai hal biasa, sementara backdoor di dalamnya bisa leluasa mengintip seluruh dunia selama puluhan tahun tanpa ada yang bisa membuktikannya!

Tiga Langkah Praktis Mengamankan Akses SSH bagi Developer dan Pemilik Server Pemula

Sebelum masuk ke tips praktis, ada tiga batasan penting (negative knowledge) yang wajib kamu tahu supaya tidak salah memakai SSH di pekerjaan sehari-hari. Pertama, jangan pernah membagikan akses terminal SSH kepada anggota tim non-teknis atau klien hanya untuk mengunggah artikel/gambar; berikan mereka akses lewat halaman dasbor CMS yang aman. Kedua, jangan menjadikan terowongan SSH sebagai pengganti VPN permanen untuk mengalirkan seluruh trafik internet kantor karena tumpukan jalur TCP di atas TCP (TCP-over-TCP) akan membuat koneksi menjadi lambat saat sinyal kurang stabil. Ketiga, ingat pelajaran dari kasus XZ Utils: sekuat apa pun enkripsi SSH milikmu, server tetap bisa jebol kalau kamu gemar memasang paket aplikasi versi uji coba (testing / unstable) yang belum matang di server utama.

Sebagaimana prinsip keamanan berlapis yang pernah kita bahas pada artikel cara mengamankan Secret API Key di server serta pelajaran dari kasus bocornya jutaan data database, kamu bisa langsung menerapkan tiga langkah sederhana ini dalam 15 menit ke depan untuk mengamankan akses SSH di VPS maupun akun GitHub/GitLab milikmu:

  1. Ganti Login Password dengan SSH Key Ed25519 Sekarang Juga: Peringatan: jangan biarkan pintu SSH di VPS milikmu hanya dijaga oleh password ketikan biasa karena ribuan bot otomatis terus mencoba menebak sandi di Port 22 sepanjang hari. Buka terminal di laptopmu, lalu buat pasangan Public Key dan Private Key modern dengan mengetik perintah ssh-keygen -t ed25519 -C "emailkamu@domain.com". Setelah gembok Public Key-nya kamu tempel ke dalam server, buka file pengaturan /etc/ssh/sshd_config di server, lalu ubah menjadi PasswordAuthentication no dan PermitRootLogin no supaya tidak ada satu pun hacker yang bisa masuk memakai tebakan password.
  2. Selalu Pakai Versi OS "Stable / LTS" untuk Server Produksi: Belajar dari kasus XZ Utils yang menyebar lebih dulu di versi uji coba (testing branch), pastikan komputer server tempat kamu menaruh website utama selalu menggunakan versi sistem operasi berlabel LTS (Long-Term Support) atau Stable Release, serta aktifkan fitur tambalan keamanan otomatis (unattended-upgrades).
  3. Pasang Firewall di Port 22 atau Gunakan Jaringan Privat: Kalau komputer server tersebut hanya dikelola oleh dirimu sendiri, jangan biarkan Port 22 terbuka bebas untuk seluruh dunia. Nyalakan pengaman seperti UFW dan Fail2ban (yang otomatis memblokir alamat IP yang salah mengetuk pintu berkali-kali), atau bungkus akses SSH milikmu di dalam jaringan privat seperti Tailscale / WireGuard agar pintu Port 22 sama sekali tidak terlihat oleh orang asing di internet publik.
